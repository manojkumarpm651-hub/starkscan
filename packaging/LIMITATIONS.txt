starkscan __VERSION__ - what this tool does NOT catch
=====================================================================
A clean report means these rules found nothing. It does not mean the
files are safe. Everything below was demonstrated against this exact
build, not inferred from reading the code.

Read this before you rely on a clean result.


1. HARDLINKS OUT OF THE SCOPE ARE REFUSED, NOT FOLLOWED
---------------------------------------------------------------------
A hardlink inside a scanned folder can name content that lives outside
it. Path resolution cannot see that: a hardlink is not a reparse
point, so the file genuinely has two equal directory entries.

Every file is therefore asked how many names it has before it is read.
A file whose content is also reachable from outside the scope is NOT
read, and the scan reports SCOPE02 naming the outside path. Pass
-follow-hardlinks to scan it anyway; the finding is still raised, so
the report always says where the content came from.

On Linux and macOS the number of names is known but their locations
are not - POSIX offers no way to map content back to its names without
walking the entire filesystem. Those files are reported as SCOPE03 and
still scanned, because "this file has another name somewhere" is not
grounds to refuse it.


2. FILES THAT ARE SILENTLY NOT SEARCHED FOR SECRETS
---------------------------------------------------------------------
  Non-Latin UTF-16.  UTF-16 itself is decoded and scanned. But a file
  is only treated as text if the decoded sample is mostly ASCII, since
  deciding a binary is text would feed every rule nonsense. A document
  written wholly in a non-Latin script fails that bar and is skipped
  by the text rules. It carries nothing those rules match anyway -
  credentials and command lines are ASCII - but the gap is real.

  Binaries.  Secrets compiled into an .exe, .dll, or database file are
  not found; the secrets check is skipped for binary content entirely.

  Archives.  A .zip, .tar.gz, or .7z holding credentials is opaque.
  Only Office macro and remote-template checks look inside a ZIP.


3. A REAL SECRET CAN BE SKIPPED BY WHAT IT SPELLS
---------------------------------------------------------------------
Values containing example, sample, test, fake, dummy, changeme,
placeholder, redacted and similar words are treated as documentation
and dropped - even when the value is a structurally valid credential.
An AWS key that happens to spell one of those words is not reported.


4. SECRETS THAT ARE NOT LITERAL TEXT
---------------------------------------------------------------------
Out of reach by construction, because this matches byte patterns:
  - split by concatenation:  "AKIA" + "2E0KZ9XQ4TRVBN51"
  - base64 or hex wrapped
  - low-entropy passphrases (correcthorsebatterystaple)
  - a download cradle split across two files (each half looks benign)


5. REPORTING CAPS AND FILTERS THAT HIDE THINGS
---------------------------------------------------------------------
  Only 15 findings per rule per file are reported, and the report does
  not say when more were withheld. A file padded with decoys can push
  real findings out of view.

  SCAN01 (file skipped, too large) and SCOPE01 (out-of-scope link
  refused) are ordinary findings subject to -min-severity. At
  -min-severity high, a run that skipped files says nothing about it.
  Keep the threshold at low if you need the coverage notices.


6. PERMISSION ANALYSIS IS SHALLOW
---------------------------------------------------------------------
It reports GRANTED BREADTH, not EFFECTIVE ACCESS.

  - Directories are never inspected, only files. A directory letting a
    broad principal create or replace files - the classic file-planting
    vector - produces no finding.
  - Deny ACEs are skipped, so a file that grants Everyone write and
    separately denies it is still reported (a false positive).
  - Group membership is not resolved. A custom group that happens to
    contain everyone is not flagged.
  - Only well-known broad SIDs are matched (Everyone, Authenticated
    Users, Users, Guests, Anonymous, Power Users).
  - On Linux and macOS only POSIX mode bits are read.


7. OPERATIONAL FOOTGUNS
---------------------------------------------------------------------
  -exclude is case-sensitive, including on Windows where the
  filesystem is not. "-exclude node_modules" does NOT exclude a folder
  named "Node_Modules". Nothing warns you.

  -out file permissions are not enforced on Windows. The 0600 mode is
  a no-op there and the report inherits the destination directory's
  ACL. A report written into a shared folder is readable by whoever
  can read that folder - including the redacted evidence and the full
  paths of every finding.

  High-entropy executables are false positives as often as not.
  Installers and self-extracting archives are indistinguishable from
  packed malware by entropy alone. That finding stays at Medium.


8. WHAT THIS IS NOT
---------------------------------------------------------------------
Not an antivirus. Outside the optional -hashes list this is pattern and
behaviour matching with no maintained signature feed. It complements an
endpoint AV product; it does not replace one.

Not a sandbox. Confinement is enforced inside the process, not by the
operating system. A bug in this program could still read outside the
selected scope, and a compromised process is not contained.

Not a compliance control. It has no notion of policy, baselines, or
evidence retention.
